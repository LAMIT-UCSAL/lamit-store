## Story

**As a** visitante decidido a comprar,
**I want** clicar em um botão "Pedir" e ser levado diretamente ao formulário de pedido correto,
**so that** eu consiga finalizar minha compra sem confusão sobre qual produto estou pedindo.

## Acceptance Criteria

1. Cada página de produto tem um CTA "Pedir" visível (FR5).
2. O CTA redireciona para o link do Google Forms configurado para aquele pedido.
3. Se o link do Forms ainda não estiver disponível no momento do desenvolvimento, o CTA usa um valor placeholder fácil de atualizar sem exigir mudanças estruturais de código.
4. O comportamento do CTA é testado manualmente em pelo menos um navegador mobile e um desktop antes do lançamento.

[Source: prd/epic-2-paginas-de-produto-encaminhamento-de-pedido.md#story-23-cta-pedir-com-redirecionamento-ao-google-forms]

**Nota de escopo (@sm):** o usuário já tem o link base do Google Forms (`https://forms.gle/fXtUpnhuPxxZenYo7`), mas o formulário ainda não tem a pergunta "Qual produto" configurada, então os links pré-preenchidos por produto (`entry.XXXXXXXXX=...`) ainda não existem. Esta story implementa o CTA usando o link base real como valor atual de `formsUrl` — cumpre a AC3 (placeholder fácil de atualizar) com um valor real, não mais um domínio inventado (`forms.gle/PLACEHOLDER`). Quando o usuário configurar as perguntas e obter os 4 links pré-preenchidos, é só atualizar `data/products.json` — nenhuma mudança de código necessária.
